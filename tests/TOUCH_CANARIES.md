# Interactive touch canaries

`touch-canaries.json` defines the repeatable tasks. An interactive user agent reads one task, observes the screen, performs its native gesture, then observes the result before choosing the next action. Do not replace a task with a call to application code or a dispatched DOM event.

Start the browser-only fixture with `node tests/render-browser-fixture.mjs`, saving its output in `render-browser.log`. It binds loopback4392 and has no cmux connection. Use the origin recorded in `state/render-fixture-info.json`. Only disposable simulator/browser tabs are test targets. Never run these recipes against Joy's existing terminals.

Before the run, record runtime, device, screen dimensions and supported input primitives. A desktop click/drag run is desktop exploration. Simulator input routed through UIKit is simulator touch. Neither is physical iPhone evidence. Unsupported hold, pinch or keyboard gestures produce `blocked`, never `pass`.

Use the iPhone 13 Pro Max CSS layout defined by `layout.viewport` in the manifest as the browser baseline, including its landscape rotation. Browser viewport resizing is layout coverage; it does not emulate Safari's native keyboard, text painting, safe areas or pinch behavior. Reduced-height browser checks are synthetic keyboard geometry, not native keyboard evidence.

For every step retain actual screen coordinates or visible targets, expected and observed outcome, and a screenshot for failures. Use synthetic fixture delivery logs to confirm exact-once key/input delivery. A highlight, open panel or HTTP success alone does not establish terminal delivery. Do not inspect or record private terminal data.

Save a report with the manifest's result fields and the source revision/time. After a fix, rerun the original failed sequence with all current UI changes active, plus adjacent tasks that share the affected interaction. Keep before and after evidence. Close only the run's own tabs, reset temporary viewport overrides, and stop only its own fixture.

For `typing-stream-paint`, start the same fixture with `POKEMUX_CANARY_ECHO=1 node tests/render-browser-fixture.mjs`. This mode streams authoritative red ASCII input and cursor updates on row6; use short ASCII words, spaces, Backspace and Left/Right. The default glyph/history fixture has no normal letter echo. Restart between modes and retain separate logs; never run competing listeners on4392. This fixture exercises the real application transport/renderer but is not cmux terminal E2E.

Simulator single-touch support does not establish multitouch or native long-hold support in the controlling tool.

Native text selection can be exercised through a double-tap and Safari's own menu when the actuator cannot hold reliably. Report double-tap selection as such, leaving long-hold acceptance open. After selection, paste, type, delete and send a modified letter; each echo must appear immediately without a second terminal tap. Reading shortcut delivery must keep the native keyboard closed.

For `delete-noop-then-type`, the echo fixture must suppress unchanged frames, as the real bridge does. An always-emitting fixture can falsely repair a missing native caret. Replay Backspace at empty followed by a letter without another terminal tap, then deletion past empty, no-op arrows, selection/paste and keyboard cycles. Sustained native Backspace is a separate duration-controlled hold task; repeated taps do not certify it.
